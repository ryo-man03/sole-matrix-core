# Release conflict resolution

Only accepted, non-unverified evidence participates in release resolution. Evidence order does not affect the semantic result. Within one independence key, the strongest/current assertion counts once; reprints do not manufacture corroboration.

When two or more independent sources report different release dates, resolution returns:

- state: `conflicting_evidence`
- resolved release date: `null`
- every distinct observed date: retained in evidence and the conflict record
- UI caution: `発売日は情報源によって異なります`

The resolver never chooses the earliest date. Pending, rejected, superseded, or unverified evidence cannot promote a state. When accepted evidence later converges, the open conflict is marked resolved; its prior record remains available for audit.

Daily Picks may use release relevance only in its separate score. A conflict reduces release urgency and availability confidence. Market price, listing count, and marketplace availability do not change taste, Core, or Ryo scores.
