# SOLE//MATRIX Core v1.1.0 — Product-ready Beta

Status: Draft on `feature/v1.1-product-ready-beta`. No v1.1.0 tag or GitHub Release is created by this work.

## Highlights

- Product home, `/login`, `/app`, `/onboarding`, and `/settings` delivery flow
- One-diagnosis guest boundary and login-equivalent session path
- Mobile-first responsive UI with a three-column desktop workspace
- Separate Ryo Mode curated recommendation seed
- Three-state satisfaction feedback and anonymized global feedback corpus
- Rakuten listing evidence excluded from Core candidates and `budgetFit`
- Gemini image and public-URL evidence with explicit confidence and warnings
- Unified external evidence panel with no direct Core Decision impact
- Settings explanations for saved data, deletion, providers, corpus, and seed policy

## Safety boundaries

- TypeScript Core remains the only owner of score and Decision.
- External evidence never enters the Core candidate set or directly changes `budgetFit`.
- Guest use does not persist personal memory.
- Runtime user data and the runtime global corpus remain gitignored.
- API keys, full queries, key-bearing request URLs, and raw provider responses are neither displayed nor logged.
- Feedback reasons redact email-like, phone-like, and URL-like values before corpus persistence.
- URL analysis continues to reject unsafe schemes, credentials, localhost, private or reserved addresses, and unsafe redirects.

## Known beta boundaries

- Login is a product/session boundary, not production authentication.
- Supabase values are placeholders for the next hosted-auth and persistence integration.
- Account deletion is documented in settings but remains disabled until an account backend exists.
- External provider credentials, quotas, and access policy remain deployment responsibilities.
- Rakuten listing evidence does not guarantee stock, fair price, seller reliability, or authenticity.
