# SOLE//MATRIX Core v0.2 CLI Usage

## 1. このドキュメントの目的

このドキュメントは、SOLE//MATRIX Core v0.2相当のCLI利用方法を、GitHub上で第三者が再現できるようにまとめたものです。

対象は、通常CLI demo、Gemini CLI demo、テスト、型チェックです。Web UI、DB、API Route、認証、外部価格API、スクレイピング、プレ値予測の実装手順は扱いません。

## 2. 前提環境

- Node.js
- pnpm
- Git
- Gemini APIキーは任意

Gemini APIキーがなくても、rule-based fallbackによりGemini CLI demoは壊れずに動きます。

## 3. install

```bash
pnpm install
```

依存関係をインストールします。意図せず `pnpm-lock.yaml` が変わった場合は、変更理由を確認してください。

## 4. 通常CLI demo

```bash
pnpm demo
```

通常CLI demoはAIを使いません。`src/data/**` のサンプルデータを `recommendSneakers(input)` に渡し、Core推薦結果を表示します。

主な表示項目:

- `finalScore`
- `rawDecision`
- `finalDecision`
- `demotions`

## 5. Gemini CLI demo

```bash
pnpm demo:gemini
```

Gemini CLI demoは、Coreが推薦結果を確定したあとに説明文生成を行います。Geminiは説明文の自然化補助のみを担当し、`finalScore`、`rawDecision`、`finalDecision`、`demotions` を変更しません。

## 6. APIキーなしでのfallback

`GEMINI_API_KEY` が未設定の場合、Gemini CLI demoはrule-based説明文にfallbackします。

表示例:

```txt
GEMINI_API_KEY not set; using rule-based fallback.
```

APIキーがない状態でも `pnpm demo:gemini` は壊れない設計です。

## 7. APIキーありでの実行方法

PowerShellで一時的にAPIキーを設定して実行する例:

```powershell
$env:GEMINI_API_KEY="your_api_key_here"
pnpm demo:gemini
```

注意点:

- APIキーをGitHubにcommitしない
- `.env` は今回作成しない
- READMEやコードに本物のAPIキーを書かない
- v0.2では `GOOGLE_API_KEY` は読まない
- Gemini APIにはレート制限があるため、無制限利用を前提にしない
- Gemini呼び出しに失敗した場合もrule-based fallbackで表示する

## 8. テスト

```bash
pnpm test
```

Core推薦ロジック、公開API、サンプルデータ、説明文生成、Gemini Adapter、CLI表示フォーマットなどの既存テストを実行します。

## 9. 型チェック

```bash
pnpm typecheck
```

`tsc --noEmit` による型チェックを実行します。

## 10. よくある失敗

- PowerShellにPrompt本文を貼ってしまう
- `PS C:\...>` を一緒に貼ってしまう
- `pnpm-lock.yaml` が意図せず変わる
- APIキーをコードに書いてしまう
- Geminiの文章でDecisionを変えようとしてしまう
- Web UI実装に早く入りすぎる

## 11. やってはいけないこと

- `src/**` を変更しない
- `package.json` を変更しない
- `pnpm-lock.yaml` を変更しない
- GitHub Actions設定を変更しない
- Geminiが購入判定を決めるように扱わない
- APIキーを直書きしない
- `.env` を作成しない
- 外部価格APIやスクレイピングの実装手順を書かない
- プレ値予測ができるように書かない
